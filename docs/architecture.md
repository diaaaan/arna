# Архитектура предметной области

## Основная сущность: Thought

`Thought` — зафиксированная пользователем мысль в её исходной форме. Это единственная первичная сущность Arna и источник истины для последующего анализа.

На концептуальном уровне мысль должна сохранять:

- неизменяемое оригинальное содержание;
- способ и время фиксации;
- технический идентификатор;
- ссылки на версии или результаты AI-анализа;
- связи с производными сущностями.

На этапе MVP `Thought` содержит поля `id`, `rawText`, `createdAt`, `updatedAt`, `source`, `status` и необязательное `analysis`. Для мыслей, введённых пользователем, `source` имеет значение `manual`, а `status` — `raw`. Поле `rawText` хранит оригинальный ввод без преобразований. Необязательность `analysis` сохраняет совместимость с ранее записанными мыслями без миграции данных.

Мысли сохраняются локально через AsyncStorage по ключу `arna.thoughts.v1`. UI не обращается к AsyncStorage напрямую: чтение и запись выполняет отдельный storage-сервис.

Capture остаётся отдельным чистым экраном для быстрой фиксации. Thought library загружает и отображает сохранённые первичные `Thought`, не изменяя их оригинальные данные или порядок в storage.

## Mind Engine

Mind Engine запускается только после успешного локального сохранения и пользовательского feedback. UI не ждёт результат AI. Pipeline выполняется в порядке: `Thought` → AsyncStorage → feedback → Gemini → runtime-валидация → `Thought.analysis` → AsyncStorage.

Prompt, сетевой Gemini-сервис, типы и валидация разделены. Модель возвращает structured output по JSON Schema, после чего приложение отдельно проверяет обязательные поля, enum-значения, confidence, items и ISO-дату. Невалидный результат сохраняется со статусом `failed`, а не принимается как интерпретация.

Каждый элемент `analysis.items` содержит `title` и явное `quantity` либо `null`, если количество не указано. При чтении старых интерпретаций строковые элементы безопасно нормализуются в `{ title, quantity: null }`; `rawText` и сами мысли при этом не удаляются и не изменяются.

Prompt имеет явную версию. Application layer добавляет `promptVersion` только после успешной валидации ответа модели; Gemini не отвечает за это поле. Старые интерпретации без версии продолжают загружаться и не запускают автоматический переанализ.

Перед каждым анализом вычисляется локальный временной контекст `Asia/Almaty`: дата, ISO datetime с UTC offset, IANA timezone и день недели. Новый контракт `dueDate` использует только ISO date `YYYY-MM-DD`. Старые сохранённые ISO datetime безопасно нормализуются при чтении в локальную дату `Asia/Almaty`.

Основная модель зафиксирована как `gemini-3.1-flash-lite`. Если API сообщает о недоступности основной модели, используется только фиксированный fallback `gemini-2.5-flash`. Автоматический выбор других или более дорогих моделей отсутствует.

`Thought.analysis` является производной интерпретацией со статусом `pending`, `success` или `failed`. Её можно повторно вычислить или удалить без потери `rawText`. Обновление анализа изменяет только производные метаданные записи и никогда не перезаписывает оригинальный текст.

На этапе локальной MVP-разработки Gemini вызывается клиентом через `EXPO_PUBLIC_GEMINI_API_KEY`. Перед публичным релизом вызовы Gemini и секрет должны быть перенесены в backend/serverless proxy; публичная переменная Expo не является безопасным местом для production-секрета.

## Почему Thought является первичной сущностью

В момент записи намерение пользователя может быть неясным даже ему самому. Если система требует сразу создать задачу, заметку или проект, она заставляет пользователя классифицировать мысль до того, как она сохранена.

`Thought` не требует предварительной интерпретации. Она точно отражает то, что ввёл пользователь, и позволяет:

- сохранить мысль до любого анализа;
- повторно анализировать её при улучшении моделей или изменении контекста;
- создавать несколько производных представлений из одного источника;
- исправлять ошибочную интерпретацию без потери оригинала;
- сохранять понятное происхождение каждой производной сущности.

## Производные сущности

После AI-анализа из мысли могут появиться:

- `Task` — конкретное действие, которое нужно выполнить;
- `ShoppingList` — перечень товаров или покупок;
- `Idea` — замысел или возможность для дальнейшего развития;
- `Project` — более крупная цель или набор связанных действий;
- `Note` — структурированная справочная информация;
- `Quote` — фраза, которую пользователь хочет сохранить отдельно;
- `Reminder` — намерение вернуться к чему-либо в определённое время или контексте.

Одна мысль может породить несколько сущностей или не породить ни одной. Производные сущности не заменяют `Thought`, а ссылаются на неё как на источник. Результаты классификации и извлечённые AI-данные должны рассматриваться как интерпретации, а не как оригинальный пользовательский ввод.

## Оригинальная мысль никогда не изменяется

После сохранения оригинальное содержание `Thought` неизменно. AI-анализ, исправления, уточнения и пользовательские преобразования записываются отдельно и не перезаписывают источник.

Если пользователь хочет исправить или дополнить мысль, система должна сохранить это как новую версию, уточнение или связанную мысль — конкретный механизм будет выбран позднее. При любых вариантах архитектуры оригинал остаётся доступным.

Этот принцип обеспечивает доверие, прослеживаемость решений AI, возможность повторного анализа и защиту от потери исходного смысла.
